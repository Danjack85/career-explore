# INFO_FEED — 信息雷达的数据来源与更新机制

## 一句话

雷达内容由 **`tools/fetch-info-feed.mjs`** 从官方来源抓取生成；App 三级降级读取
（远程 feed → 本地缓存 → 随包内置），所以任何情况下都有内容可看。

## 为什么只自动抓「标题 / 链接 / 日期」

`docs/SCHEMA.md` 里一条信息有四个描述字段，它们的性质不同：

| 字段 | 性质 | 能否自动生成 |
| --- | --- | --- |
| `summary`（发生了什么） | 事实 | 标题即原文事实，够用；细节点开原文 |
| `impact`（意味着什么） | **判断** | ❌ 不能 |
| `action`（该做什么） | **判断** | ❌ 不能 |

后两项如果由脚本生成，就是**编造结论** —— 直接违反 `docs/PRD.md` 的
「事实 / 观点 / 猜测分开」和 AGENTS.md 的「不伪造行业数据」。

而且这两项恰恰是用户自己要做的判断，不是产品该替他做的。
所以 feed 里它们**留空**，App 中显示为待填写，由用户自己写（`src/api/infoNotes.ts`，
存本地，按 feed 条目 id 关联）。

> 结论：自动化的边界划在「事实」这一侧。

## 抓取脚本

```bash
node tools/fetch-info-feed.mjs            # 抓取并写入 src/mock/infoFeed.generated.json
node tools/fetch-info-feed.mjs --dry-run  # 只打印，不写文件
```

行为：

- 来源见脚本里的 `SOURCES` 常量。当前 5 个列表页：

| 来源 | 栏目 | 等级 |
| --- | --- | --- |
| 国家统计局 | 最新发布 | 官方数据 |
| 国家统计局 | 数据解读 | 官方数据 |
| 教育部 | 工作动态 | 官方数据 |
| 教育部 | 政策文件 | 官方数据 |
| 国家发展改革委 | 新闻发布会 | 官方数据 |

- 只请求列表页，**不抓正文**（正文提取脆弱，且标题已足够说明发生了什么）。
- 低并发、带 User-Agent 标识、超时 20 秒。
- 相关性过滤（`KEYWORD_TAGS`），与「找方向」无关的条目不进雷达；同一份表也用来生成标签。
  关键词表刻意**不写宽泛的「教育」二字** —— 教育部站点几乎所有标题都含「教育」，
  会捞进「青少年宪法法治教育座谈会」这类无关条目；只保留高等教育 / 就业培养的具体词。
- 噪声过滤（`NOISE_PATTERN`）：会见、贺信、致辞等礼仪外事类，以及运动会 / 锦标赛等体育赛事。
  这类标题没有可行动的信息，还会被关键词误伤（实测「会见芬兰经济事务与**就业**部长」曾被标成就业类）。
- 去重：先按 URL，再按标题前 24 字；列表页的截断标题（`...` 结尾）直接丢弃。
- **每来源配额 3 条**，且**先按来源各取最新若干、再合并排序**。
  反过来先全局排序再限流是错的：较老的来源会被整段饿死，一条都进不来（踩过）。
- **抓到 0 条时报错退出，不写入文件** —— 避免站点改版时用空 feed 覆盖已有数据。

### 已确认抓不到的来源

| 来源 | 原因 |
| --- | --- |
| 人社部 | 返回 JS 反爬脚本（响应仅 986 字节） |
| 工信部 | 首页几乎无可解析条目 |
| 人民网 | HTTP 403 |
| 中国新闻网 | HTTP 403（财经频道同样被拦） |
| 新华网 | 页面可访问，但**日期抓取不可靠**（全部解析成同一个静态元素日期），宁可不用 |

**因此「深度媒体」这一档目前仍缺位。** 券商研报、招聘平台报告多为 PDF 或需授权，
不适合自动抓取；深度媒体有反爬。这两档都需要**人工录入**。
雷达的可信度结构应该是多档并存，目前只有「官方数据」一档，是有待补的短板。

## App 侧的读取（三级降级）

`src/api/infoFeed.ts`：

```
1. remote   配置了 VITE_INFO_FEED_URL → 拉取成功则写入本地缓存
2. cache    上次成功拉取的缓存，6 小时内直接命中（避免每次打开都请求）
3. bundled  随 App 打包的 feed（scripts 生成的那份）
```

- 远程拉取**失败不会清空已有数据**：降级到缓存或内置，并在页面顶部显示失败原因。
- 远程 feed 视为**不可信输入**：逐字段校验（标题 / 链接 / 来源 / 来源等级 / URL 协议），
  非法条目直接丢弃，坏数据不会把页面搞崩。
- `version` 高于 `SUPPORTED_FEED_VERSION` 的 feed 会被拒绝使用（防止字段语义变化后误读）。

## 怎么做到「不重新打包就更新」

1. 跑脚本生成 feed（或手工维护一份 JSON）。
2. 把它放到任意静态托管，拿到直链。GitHub Pages、对象存储、Supabase Storage 都行。
3. 把直链填到 `.env` 的 `VITE_INFO_FEED_URL`，重新打包**一次**。
4. 此后更新内容只需替换托管上的 JSON，App 里点「刷新」即可拿到，不用再打包。

**为什么必须走 feed 文件、不能在 App 里直接抓政府站点：**

- 政府站点**不发 CORS 头**，WebView 里直接 fetch 会被拦。
- 即便在 APK 里用原生请求绕过 CORS，也不该在客户端做 HTML 解析 ——
  站点一改版就要发新版 App 救火。解析放在构建期，客户端只吃 JSON。

## feed 格式

```json
{
  "version": 1,
  "generated_at": "2026-09-22T13:16:46.284Z",
  "items": [
    {
      "id": "info-6a5b3674fd4a",
      "title": "2026年8月份规模以上工业增加值增长5.2%",
      "source_name": "国家统计局",
      "source_level": "官方数据",
      "url": "https://www.stats.gov.cn/...",
      "published_at": "2026-09-15",
      "summary": "",
      "impact": "",
      "action": "",
      "tags": ["制造业", "最新发布"],
      "created_at": "2026-09-22T13:16:46.284Z"
    }
  ]
}
```

约定：

- `id` 由 URL 的 sha1 前 12 位派生，**跨次生成保持稳定** —— 否则用户写的批注会在
  feed 更新后错位到别的条目上。
- `source_level` 必须落在 `docs/SCHEMA.md` 的六档枚举内。
- `published_at` 拿不到时写「待核实」，不编日期。
- `summary` / `impact` / `action` 允许为空字符串。

## 相关：行业卡片的来源（`fetch-industry-evidence.mjs`）

信息雷达（本文件）解决的是「每周有什么新信息」；行业卡片的来源是另一条线，
由 `tools/fetch-industry-evidence.mjs` 生成到 `src/mock/industryEvidence.generated.json`。

两者的共同原则完全一致，可以对照看：

| | 信息雷达 | 行业卡片 |
| --- | --- | --- |
| 自动抓的 | 标题 / 链接 / 日期 | 官方统计**原句** + 链接 + 日期 |
| 不由机器生成的 | `impact`（意味着什么）<br>`action`（该做什么） | `stage`（阶段）<br>`risks`（风险） |
| 原因 | 那是判断，机器生成等于编造结论 | 同上 |
| 谁来做判断 | **用户自己写**（`src/api/infoNotes.ts`） | 编辑写，但必须标明是判断 |

行业卡片还有一条额外的硬规矩：**指标必须与行业直接对应**。
用宽口径数字（如「第三产业投资」）去撑具体行业（如「企业服务 SaaS」）属于隐含的过度关联，
与编造数据同类，脚本里明确不做。因此 10 个行业里只有 3 个挂上了官方统计，
其余 6 个显式标注「官方统计未单列该口径」，1 个挂的是政策文件。

`quote` / `impact` / `action` 三个字段的共同点是：**允许为空，且界面必须如实说明为什么为空**。

- 内置 feed：**9 条**，来自国家统计局 / 教育部 / 国家发展改革委各 3 条，
  抓取时间见文件里的 `generated_at`。
- 未配置远程 feed（`.env` 里 `VITE_INFO_FEED_URL` 为空），
  所以「刷新」暂不联网，用的是随包数据。
- **来源等级只有「官方数据」一档**。`docs/SCHEMA.md` 定义的另外五档
  （招聘平台报告 / 券商研报 / 深度媒体 / 从业者访谈 / 自媒体）需要人工补充 ——
  自动抓取已确认拿不到（见上表）。这是雷达目前最大的短板：
  六档并存是可信度结构的设计意图，单一来源无法交叉验证。
