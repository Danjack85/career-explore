# FLOW — 主流程与实验闭环

## 主流程

```
首页
 └── 选择卡点（四选一）
      ├── A 不知道有哪些行业      → 行业地图
      ├── B 不知道自己适合什么    → 探索测评
      ├── C 信息太乱、看不完      → 信息雷达
      └── D 有方向但执行不下去    → 计划与实验
            └── 加入实验（所有路径最终汇入这里）
```

四个卡点不是四个平级功能入口，而是**四种进入实验的路径**。用户在任一功能停留超过预期，都应有一条「先做个小实验」的出口。

| 卡点 | 用户原话 | 功能 | 出口 |
| --- | --- | --- | --- |
| A | 不知道都有什么行业 | 行业列表 → 详情 | 用这个行业直接开始一次 7 天实验 |
| B | 不知道自己喜欢什么 | 测评 → 结果页 | 从关键词生成 2-3 个方向 |
| C | 信息太多看不过来 | 信息雷达 | 把一条信息变成本周动作 |
| D | 有计划但做不动 | 计划页 | 把本月实验拆成本周动作 |

> **关于卡点 A 的出口**：最初设想是「把这个行业加进待实验清单」，实现时改为**直接创建实验**。
> 理由：所有路径最终都要汇入实验，中间多一层「待实验清单」只会多一个没人维护的状态；
> 用户点完按钮就进入 7 天实验，比先攒进一个清单更接近「先做个小实验」的产品主张。

## 实验闭环

一个实验 = 一次 7 天的低成本试错。核心是**记录能量和喜恶**，不是完成任务。

```
选方向
  → 写假设（我猜……做了……之后，我会……）
  → 7 天任务（每天 <= 30 分钟，能在宿舍/工位完成）
  → 每天记录：能量 + 今天喜欢的 + 今天讨厌的
  → 第 7 天复盘
  → 输出结论：继续 / 排除 / 换方式
```

### 各环节要求

**选方向**：可以很粗（「数据分析」「产品运营」），不要求精确到岗位。

**写假设**：必须可证伪。
- 好：「我猜做完 7 天 SQL 练习后，我会愿意继续做下去。」
- 差：「我要提升数据分析能力。」（不可证伪，也不是假设）

**7 天任务**：每天 <= 30 分钟。任务过大是实验失败的第一原因。

**每日记录**：
- 能量：1-5 分（做完这件事**之后**的感觉）
- 喜：今天哪个瞬间不觉得累
- 厌：今天哪个瞬间想放弃

**第 7 天复盘**：三个问题
1. 能量曲线整体往上还是往下？
2. 讨厌的瞬间是「这件事本身」还是「这件事的形式」？
3. 下一步：继续 / 排除 / 换方式？

### 最小可观察信号

- **继续**：平均能量 >= 3，且至少 3 天出现「喜」。
- **换方式**：能量低，但「厌」集中在形式（枯燥、要早起、工具难用）。
- **排除**：能量持续 <= 2，且「厌」集中在事情本身。

排除一个方向是**有效结果**，复盘页必须显式说明，避免用户把「排除」理解成失败。
